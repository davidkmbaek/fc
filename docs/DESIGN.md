# 게임 설계 문서 (DESIGN)

이 문서가 게임 사양의 단일 기준이다. 수치는 **초기값**이며 `src/config.ts`에서 튜닝한다.
사양을 바꾸면 이 문서도 함께 고치고, `docs/PROGRESS.md`의 결정 기록에 남긴다.

---

## 1. 비전과 범위

- **목표 경험**: 탑뷰 2D, 빠르고 직관적인 조작, 패스를 주고받는 재미, 그럴듯하게 움직이는 AI.
- **범위 안**: 1P vs AI, 로컬 2P, 5:5 → 11:11, 키보드·게임패드, 기본 경기 규칙, 난이도.
- **범위 밖**: 온라인 멀티플레이, 실존 구단·선수·상표, 커리어 모드, 모바일 터치 조작(나중에 검토).
- **나중에 (5단계 이후 검토)**: 파울·카드, 오프사이드, 공 회전(감아차기), 리플레이.

## 2. 좌표계와 경기장 규격

### 좌표계

- 단위: 미터(m), 초(s).
- 원점: 센터 스팟. `x`는 경기장 길이 방향(-52.5 ~ +52.5), `y`는 폭 방향(-34 ~ +34), `z`는 높이(위쪽이 +).
- 화면에서는 `x`가 오른쪽, `y`가 아래쪽.
- 전반전에는 홈 팀이 +x 방향으로 공격한다. 후반전에는 진영을 바꾼다.

### 규격 (실제 축구장 기준)

| 항목 | 값 |
|---|---|
| 경기장 | 105 × 68 |
| 골대 폭 / 높이 / 깊이 | 7.32 (골포스트 y = ±3.66) / 2.44 / 2.0 |
| 골포스트·크로스바 두께 | 반지름 0.06 |
| 페널티 에어리어 | 골라인에서 16.5, 폭 40.32 (y = ±20.16) |
| 골 에어리어 | 골라인에서 5.5, 폭 18.32 (y = ±9.16) |
| 페널티 스폿 | 골라인에서 11 |
| 센터 서클, 페널티 아크 반지름 | 9.15 |
| 코너 아크 반지름 | 1.0 |
| 라인 두께 | 0.12 |
| 공 반지름 | 0.11 |
| 경기장 밖 여백 (렌더링·선수 이동 가능 영역) | 사방 6 |

## 3. 공 물리

### 상태

`pos (x, y, z)`, `vel (vx, vy, vz)`, `lastTouch { playerId, teamId, time }`

### 매 스텝 처리 (dt = 1/60)

1. **공중** (`z > 0` 또는 `vz > 0`)
   - `vz -= GRAVITY * dt`
   - 공기 저항: `a = AIR_DRAG * |v|²`, 속도 반대 방향
2. **착지**: `z <= 0`이고 `vz < 0`이면
   - `z = 0`, `vz = -vz * BOUNCE_RESTITUTION`
   - 수평 속도에 `BOUNCE_FRICTION`을 곱함
   - `vz < BOUNCE_STOP_VZ`이면 `vz = 0`으로 두고 굴러가는 상태로 전환
3. **굴러감** (`z = 0`, `vz = 0`)
   - 수평 감속: `|v| -= (ROLL_DECEL + ROLL_DAMPING * |v|) * dt`, 0 아래로 내려가지 않게
   - `|v| < STOP_SPEED`이면 정지
4. **충돌**: 골포스트(원기둥), 크로스바(`z = 2.44` 높이의 가로 막대), 골망(골 안쪽에서 속도를 크게 줄임). 선수 충돌은 §4 참고.

### 초기 수치

| 상수 | 값 | 비고 |
|---|---|---|
| `GRAVITY` | 9.81 | m/s² |
| `AIR_DRAG` | 0.013 | 실제 축구공에 가까운 값 (30 m/s에서 약 12 m/s² 감속) |
| `BOUNCE_RESTITUTION` | 0.55 | 잔디 |
| `BOUNCE_FRICTION` | 0.85 | 바운드할 때 수평 속도 유지 비율 |
| `BOUNCE_STOP_VZ` | 0.6 | |
| `ROLL_DECEL` | 2.0 | m/s² |
| `ROLL_DAMPING` | 0.25 | 1/s |
| `STOP_SPEED` | 0.05 | |
| `POST_RESTITUTION` | 0.7 | |
| 슛 최대 속도 | 30 | m/s |
| 땅볼 패스 속도 범위 | 6 ~ 22 | m/s |

### 판정 (테스트 필수)

- **골**: 공 **전체**가 골라인을 넘어야 한다: `|x| > 52.5 + 0.11`. 동시에 골포스트 사이(`|y| < 3.66 - 0.11`)이고 크로스바 아래(`z < 2.44 - 0.11`)여야 한다.
- **아웃**: 공 전체가 터치라인(`|y| > 34 + 0.11`)이나 골라인을 넘으면 아웃. `lastTouch` 팀을 기준으로 재시작 종류를 정한다.
- 판정은 매 스텝 이전 위치와 현재 위치를 비교해서, 한 스텝에 라인을 건너뛰는 경우도 놓치지 않는다.

### 나중에: 공 회전

감아차기는 5단계 이후. 진행 방향에 수직인 횡가속도를 `spin` 값으로 주고, 시간이 지나면 감쇠시키는 방식으로 구현한다.

## 4. 선수

### 물리

| 항목 | 값 |
|---|---|
| 충돌 반지름 | 0.4 |
| 키 | 1.8 |
| 달리기 / 스프린트 최고 속도 | 6.0 / 8.0 m/s |
| 공을 몰고 갈 때 속도 배율 | 0.9 |
| 가속 / 감속 | 7 / 10 m/s² |
| 최대 회전 속도 | 저속 720°/s → 스프린트 270°/s (속도에 따라 보간) |

- 선수끼리는 원 충돌로 서로 밀어낸다. 공을 가진 선수가 부딪히면 잠깐 느려진다.
- **공에 닿는 높이**: 발 `z < 0.6`, 몸·가슴 `0.6 ~ 1.5`(트래핑), 머리 `1.5 ~ 2.4`(헤딩, 점프 포함).

### 볼 컨트롤과 드리블

- 공은 선수에게 "붙어" 있지 않는다. 드리블은 **작은 터치의 반복**이다.
- **컨트롤 가능 조건**: 공이 `CONTROL_RADIUS`(0.8) 안에 있고, `z < 0.6`이고, 상대 속도가 `CONTROL_MAX_REL_SPEED`(7) 미만.
- **터치**: 컨트롤 가능하면 이동 방향으로 공을 살짝 찬다. 공 속도는 `선수 속도 + TOUCH_BOOST`이고, `TOUCH_BOOST`는 일반 1.2, 스프린트 3.0이다. 터치 쿨다운은 0.25초. 스프린트하면 공이 멀리 나가서 뺏기기 쉬워진다.
- **볼 소유자**: 마지막으로 터치했고 공이 `CONTROL_RADIUS × 2` 안에 있는 선수. AI와 UI가 이 값을 쓴다.

### 태클

- **스탠딩 태클**: 범위 1.3. 성공 확률은 공과의 거리와 상대 진행 방향 대비 각도로 정하고, 시드 RNG로 판정한다. 실패하면 0.4초 동안 행동 불가.
- **슬라이딩 태클**: 9 m/s로 3.5m 미끄러지고, 이후 0.8초 동안 행동 불가. 공을 먼저 맞히면 공이 튕겨 나간다. 사람을 먼저 맞히는 경우는 파울 도입 전까지 둘 다 넘어지는 것으로 처리한다.

## 5. 조작과 액션

### 키 배치 (설정에서 변경 가능)

| 동작 | 키보드 | 게임패드 (Xbox 기준) |
|---|---|---|
| 이동 | 방향키 | 왼쪽 스틱 |
| 짧은 패스 / (수비) 스탠딩 태클 | S | A |
| 로빙 패스·크로스 / (수비) 슬라이딩 | A | B |
| 스루패스 | W | Y |
| 슛 | D | X |
| 스프린트 | E | RT |
| 선수 전환 | Q | LB |
| 일시정지 | Esc | Start |

### 액션 인터페이스

입력 계층은 키를 누른 시간 등을 해석해서 매 스텝마다 아래 형태의 의도(intent)를 만든다. AI도 같은 형태를 만든다.

```ts
interface PlayerIntent {
  move: Vec2;            // 크기 0~1
  sprint: boolean;
  kick?: { type: 'pass' | 'through' | 'lob' | 'shot'; power: number /*0~1*/; aim: Vec2 };
  tackle?: 'stand' | 'slide';
  switchPlayer?: boolean; // 사람만 사용
}
```

### 세부 규칙

- **킥 세기**: 버튼을 누르고 있는 시간으로 정한다. 최대 1.0초, 선수 위에 파워 게이지를 표시하고, 버튼을 떼는 순간 실행한다.
- **입력 버퍼**: 공을 갖고 있지 않을 때 누른 킥 입력은 0.15초 동안 유지한다. 그 사이에 공이 오면 원터치로 실행한다.
- **패스 대상 선택**
  - 조준 방향(스틱 방향, 입력이 없으면 선수가 보는 방향) ±35° 안의 동료를 후보로 잡는다.
  - 각도, 거리, 차단 위험(§7 패스 안전도)으로 점수를 매겨 가장 좋은 동료에게 준다.
  - 후보가 없으면 조준 방향으로 찬다.
- **땅볼 패스 속도**: 받는 사람에게 `ARRIVE_SPEED`(약 5 m/s)로 도착하도록 초기 속도 `v0`를 계산한다.
  - §3의 굴러감 모델 `dv/dt = -(a + b·v)`(a = `ROLL_DECEL`, b = `ROLL_DAMPING`)에서, `v0`에서 `v1`까지 속도가 줄어드는 동안 이동한 거리는 `d = (v0 - v1)/b - (a/b)·t`이고, 걸린 시간은 `t = (1/b)·ln((v0 + a/b)/(v1 + a/b))`이다.
  - 이 식으로 목표 거리 `d`에 맞는 `v0`를 이분법으로 구한다(`sim/math/`에 함수로 두고 테스트).
  - 누른 세기는 계산된 값에 ±30% 정도 영향을 준다.
  - 참고: 초기 수치에서 15 m/s 땅볼은 약 26m, 22 m/s는 약 46m 굴러간다.
- **스루패스**: 받을 동료의 예상 위치(현재 위치 + 달리는 방향 × 공 도착 시간 × 속도)로 보낸다. 받는 동료의 AI에게 그 지점으로 달리라고 지시한다.
- **로빙 패스·크로스**: 목표 지점까지의 체공 시간을 정해 `vz`와 수평 속도를 계산한다.
- **슛**
  - 방향은 상대 골문 안의 목표점으로 정한다. 스틱으로 가까운 포스트와 먼 포스트를 고를 수 있다.
  - 부정확도(각도 오차) = 기본값 + `power²` × 계수 + 압박(가까운 수비수 수) × 계수.
  - 세게 찰수록 `vz`가 커져서 크로스바를 넘길 위험이 생긴다.
- **선수 전환**
  - 수비 시: 공까지 **도달 시간**이 가장 짧은 동료로 바꾼다.
  - 스틱을 기울이고 누르면 그 방향의 동료로 바꾼다.
  - 패스를 받을 동료로 자동 전환하는 옵션을 둔다(기본 켜짐).

## 6. 경기 흐름 (상태 머신)

```
PreMatch → KickOff → InPlay
InPlay → GoalScored(세리머니 3초) → KickOff (실점한 팀이 킥오프)
InPlay → OutOfPlay → SetPiece(ThrowIn | CornerKick | GoalKick) → InPlay
InPlay → HalfTime → KickOff(진영 교체) → InPlay → FullTime
```

- **재시작 종류**: `lastTouch` 팀과 공이 나간 라인으로 정한다.
  - 터치라인 → 상대 팀 스로인
  - 골라인 + 수비팀이 마지막 터치 → 코너킥
  - 골라인 + 공격팀이 마지막 터치 → 골킥
- **세트피스 준비**: 선수들이 정해진 위치로 빠르게 이동하고(최대 2초, 이후에는 순간이동), 키커가 공을 받으면 `InPlay`로 넘어간다. 킥오프와 코너킥 때 상대 팀은 9.15m 밖에 서 있어야 한다.
- **스로인**: 손으로 던지는 짧은 로빙 패스로 단순화한다(최대 25m).
- **시간**: 전·후반 실제 시간 기본 3분(설정 가능). 화면 시계는 45분으로 환산해서 보여준다. 시계는 `InPlay`일 때만 흐른다.

## 7. AI

Mat Buckland, *Programming Game AI by Example* 4장 "Simple Soccer"의 구조를 따른다.

### 공통 유틸리티 (테스트 필수)

- **도달 시간 `timeToReach(player, point)`**: 현재 속도, 가속, 회전을 단순 근사해서 계산한다. "가장 가까운 선수"는 항상 거리가 아니라 **도달 시간**으로 판단한다.
- **공 가로채기 지점 `interceptPoint(player, ball)`**: 공의 예상 궤적(굴러감, 공중 포함)을 시간 순으로 샘플링해서, 선수가 공보다 먼저 도착할 수 있는 첫 지점을 찾는다.
- **패스 안전도 `passSafety(from, to, speed)`**: 공의 경로 위 각 지점에 대해 상대 선수의 도달 시간을 공 도달 시간과 비교한다. 상대가 여유 시간 안에 먼저 도착할 수 있으면 위험한 패스로 본다.

### 팀 상태

- `Attacking`(우리 팀이 볼 소유), `Defending`, `SetPiece`.
- **포메이션**: 5:5는 GK-2-1-1(수비 2, 미드필더 1, 공격수 1), 11:11은 4-4-2. 각 포지션의 홈 위치는 팀 상태에 따라 다르게 정하고, 공의 x 위치에 따라 팀 전체가 앞뒤로 이동한다(`x` 이동 = 공 x × 0.4, 폭은 공 쪽으로 약간 좁힘).

### 선수 상태

| 상태 | 설명 |
|---|---|
| `HoldPosition` | 홈 위치를 유지한다. 가까우면 공 쪽을 바라본다. |
| `ChaseBall` | 아무도 소유하지 않은 공에 팀에서 도달 시간이 가장 짧은 1명만 간다. |
| `Dribble` | 압박이 적은 방향, 상대 골문 쪽으로 몬다. |
| `KickDecision` | 슛 → 전진 패스 → 안전한 패스 → 드리블 순으로 판단한다. 슛은 거리, 골문 각도, 앞을 막는 수비수로 기대값을 계산해서 임계값을 넘으면 찬다. |
| `ReceiveBall` | 패스 도착 지점(스루패스면 예상 지점)으로 이동한다. |
| `Support` | 볼 소유자 근처의 최적 지원 위치로 이동한다(아래 참고). |
| `Press` | 수비 시 볼 소유자에게 도달 시간이 가장 짧은 1명이 압박한다. |
| `Mark` | 수비 시 나머지는 가장 위협적인 상대를 마크하거나 패스 길을 막는 위치로 간다. |
| `ReturnHome` | 홈 위치로 복귀한다. |

- **지원 위치 계산**: 공격 진영에 격자 점을 샘플링하고 0.5초마다 다시 계산한다. 점수 = 볼 소유자로부터의 패스 안전도 + 그 위치에서의 슛 가능성 + 볼 소유자와의 이상적인 거리(약 15m).
- **결정 주기**: AI는 매 스텝이 아니라 0.1~0.2초마다 판단을 다시 한다. 이동 자체는 매 스텝 적용한다.

### 골키퍼

- 공과 골문 중앙을 잇는 선 위에 선다. 골라인에서의 거리는 공이 멀수록 나오고(0.5~4m), 가까울수록 들어간다.
- 슛이 오면 가로채기 지점으로 다이빙한다(0.5초 동안 빠른 횡이동). 닿으면 공이 느릴 때는 잡고, 빠를 때는 쳐낸다.
- 페널티 에어리어 안의 흘러나온 공은 도달 시간이 가장 짧으면 나가서 처리한다.
- 공을 잡으면 1~2초 뒤 비어 있는 동료에게 던지거나 찬다.

### 난이도 파라미터

반응 시간(0.15~0.4초), 결정 주기, 킥 정확도 노이즈, 패스를 고려하는 최대 거리, 압박 강도.

## 8. 렌더링

- **레이어 순서**: 경기장(시작할 때 한 번만 그려서 텍스처로 저장) → 골망 뒷부분 → 그림자 → 선수(`y` 기준 정렬) → 공 → 골포스트·크로스바 앞부분 → 선수 표시(조작 선수 화살표, 파워 게이지) → HUD 씬(점수, 시계, 미니맵).
- **공 그리기**: 그림자는 `(x, y)`에 그리고 높이가 높을수록 흐리고 작게. 공은 `(x, y - z × Z_SCREEN_SCALE)`에 그린다(`Z_SCREEN_SCALE` ≈ 0.7). 크기 배율은 `1 + z × 0.08`.
- **보간**: 렌더링 위치 = 이전 상태와 현재 상태를 `alpha`(누적기 잔여 시간 / dt)로 보간한 값.
- **카메라**: 목표점은 공 위치 + 공 속도 × 0.3초(진행 방향을 미리 보여줌). 부드럽게 따라가고, 데드존을 두고, 경기장과 여백 밖으로 나가지 않게 한다. 화면 너비에 약 40m가 보이는 줌을 기본값으로 한다.
- **조작 선수 표시**: 팀 색 화살표를 표시한다. 화면 밖에 있으면 가장자리에 방향 표시를 띄운다.
- **해상도**: Phaser Scale `FIT` 모드, 16:9 기준.

## 10. 테스트 전략

- **단위 테스트 (Vitest)**
  - 공 물리: 높이 2m에서 떨어뜨리면 튈 때마다 최고 높이가 줄어든다. 굴러가는 공은 결국 멈추고, 이동 거리가 예상값 ±10% 안에 든다.
  - 골 판정: 라인을 완전히 넘었을 때만 골, 크로스바 위는 골이 아님, 골포스트를 맞으면 튕김. 한 스텝에 라인을 건너뛰는 빠른 공도 판정한다.
  - 아웃 판정과 `lastTouch`에 따른 재시작 종류.
  - 패스 속도 공식: 목표 거리에서 도착 속도가 `ARRIVE_SPEED` ±1 m/s 안에 든다.
  - `timeToReach`, `interceptPoint`, `passSafety`.
  - RNG 결정성: 같은 시드는 같은 수열을 만든다.
- **시뮬레이션 테스트**
  - AI 대 AI 5분 경기(헤드리스)를 돌려서 예외가 없는지 확인한다. 또 NaN이 없어야 하고, 공이 월드 밖으로 나가지 않아야 하며, 한 상태가 10초 이상 멈춰 있지 않아야 한다(정체 감지).
  - **결정성**: 같은 시드와 같은 입력 기록이면 마지막 상태의 해시가 같아야 한다.
- **수동 체크리스트**: 각 단계의 완료 조건(§11)을 브라우저에서 직접 확인한다.

## 11. 로드맵과 완료 조건

각 하위 단계는 한 번의 작업 단위다. 완료 조건을 모두 만족해야 다음 단계로 간다.

### 0단계 — 기반

- 0.1 Vite + TS(strict) + Phaser 4 + ESLint/Prettier + Vitest 세팅, `npm run check` 구성
- 0.2 §2 규격대로 경기장 그리기 (라인, 에어리어, 서클, 골대)
- 0.3 GitHub Actions로 Pages 배포
- 0.4 고정 스텝 루프 + 보간, 디버그 오버레이 뼈대, Tweakpane 연결, 일시정지·스텝·슬로모션

**완료 조건**: 배포 URL에서 경기장이 보인다 / `npm run check` 통과 / 백틱 키로 FPS 오버레이가 켜진다.

### 1단계 — 공과 선수 1명

- 1.1 공 시뮬레이션(z축, 바운드, 굴러감)과 테스트, 그림자 렌더링, 클릭으로 공 발사하는 개발 도구
- 1.2 골포스트·크로스바·골망 충돌, 골·아웃 판정과 테스트
- 1.3 선수 이동(관성, 스프린트, 회전 제한)과 카메라
- 1.4 드리블 터치, 슛(파워 게이지)
- 1.5 시나리오 시스템(`?scenario=freeplay`, `penalty`)

**완료 조건**: 드리블해서 골을 넣을 수 있다 / 공이 골포스트와 크로스바에 튕긴다 / 크로스바를 넘긴 슛은 골이 아니다 / 테스트 통과.

### 2단계 — 팀 조작 (상대는 아직 가만히 서 있음)

- 2.1 5:5 포메이션 배치, 선수끼리 충돌
- 2.2 짧은 패스, 스루패스, 로빙 패스와 패스 대상 선택
- 2.3 선수 전환과 조작 선수 표시
- 2.4 스탠딩 태클, 슬라이딩 태클
- 2.5 입력 버퍼와 원터치 패스

**완료 조건**: 우리 팀끼리 패스를 5번 이상 연결할 수 있다 / 원터치 패스가 된다 / 상대에게서 공을 태클로 뺏을 수 있다.

### 3단계 — AI

- 3.1 `timeToReach`, `interceptPoint`, `passSafety`와 테스트
- 3.2 팀 상태와 포메이션 이동
